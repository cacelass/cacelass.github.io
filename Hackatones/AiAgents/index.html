AIAgents

Diseño y arnés de una fábrica personal de agentes: un solo propietario especifica, construye y evalúa agentes sobre su propio equipo, con las reglas del juego escritas en código.

¿Qué es?

Un repositorio que implementa un arnés de trabajo para proyectos asistidos por IA. No es un chatbot: es un ciclo con puerta de entrada, backlog verificado y puertas de permisos para las acciones irreversibles.

Las reglas del juego están escritas en código, no en un prompt. La puerta de entrada decide si se puede trabajar, el backlog tiene criterios de aceptación explícitos, la memoria vive fuera de la ventana de contexto y hay una puerta de permisos para las acciones que no se deshacen.

Arquitectura

🚪 init.sh

La puerta: ¿se puede trabajar? Verifica entorno, estructura del arnés y que los tests pasan en verde. Si falla, para.

📋 featureslist.json

Backlog con criterios de aceptación explícitos. Cada feature tiene qué, cómo y por qué medible.

🧠 harness/progress/

Memoria fuera de la ventana de contexto: tarea actual, histórico y estado de las features.

🔐 Permissions

Matriz de permisos, datos y secretos coherente. Acciones irreversibles requieren aprobación.

Sistema de agentes

24 agentes Python deterministas, cada uno con un contrato de rol definido:

  • lider — dirige el ciclo, elige la siguiente feature del backlog
  • explorer — investiga en solo lectura, sin modificar nada
  • implementer — escribe código y tests
  • reviewer — aprueba o rechaza el trabajo del implementer
  • documentación — mantiene CHANGELOG, README y docs al día
  • CI/CD — gestiona pipelines y verificación continua
  • dependencias — analiza y actualiza dependencias del proyecto
  • secretos — detecta y rota secretos expuestos en el código
  • testing — genera y mantiene la suite de tests
  • linting — mantiene el código limpio y consistente

Cada agente sigue un contrato: qué hace, qué no hace y qué evidencia debe aportar. La política de herramientas se activa manualmente según `AGENTS.md`.

¿Cómo se usa?

El ciclo de trabajo es simple:

# 1. Verificar que se puede trabajar make init # 2. Ver estado del backlog make run # o sin instalar: uv run python -m meshharmes status # 3. Ejecutar verificación completa make check # 4. Cerrar feature con git commit_feature git commit_feature --dry-run # (el agente propone, tú confirmas)

El protocolo completo está en AGENTS.md. La regla que no se salta: ninguna feature se cierra sin que make init pase en verde.

Conocimiento y RAG

El proyecto incluye un vault de conocimiento en vault/, con indexación RAG local opcional y grafo de conocimiento con graphify. Todo el conocimiento profundo del proyecto se consulta antes de decidir, no se asume.
