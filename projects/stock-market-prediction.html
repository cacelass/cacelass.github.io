Stock-Market-Prediction · time series · finance

Financial time series
evaluated honestly.

Directional price movement prediction in a non-stationary, low signal-to-noise domain, where the stated goal is not profitability but facing overfitting and data leakage rigorously. Walk-forward validation, out-of-sample backtest with costs, hybrid per-ticker routing and real news sentiment.

«Existen numerosas formas de arruinarte. De entre ellas, crear un algoritmo de machine learning que trate de predecir el valor de las acciones en bolsa para luego invertir tu dinero, es una de las más rápidas y efectivas.»

Exploración técnica de Machine Learning aplicado a series temporales financieras. El objetivo no fue buscar rentabilidad, sino enfrentarse a un problema real con alta incertidumbre y aprender de los errores — especialmente del overfitting y del data leakage.

problem

What it solves

Predict whether an asset rises more than 2% in 5 days using Random Forest over multi-ticker data plus sentiment features. The honest framing is explicit: most published results in this domain fail out-of-sample, and this project treats that as the problem to solve: not a model to squeeze.
Task
Binary classification, 7 tickers · RF + VADER sentiment + NewsAPI.ai real news
Rigour
175 tests · mypy strict · walk-forward 3-fold · Optuna tuning · anti-leakage in code
Ops
FastAPI · PSI drift monitoring · hybrid per-ticker routing · ONNX-ready
decisions

Engineering decisions

→ Walk-forward is the only honest evaluation: 3-fold expanding window. The single 80/20 split inflated accuracy from 54.1% to 57.7% — discovered and corrected.
→ Scaler fitted on train only: the test set never touches the scaler.
→ Target built with shift(-5): the future only labels, never leaks into features.
→ RandomForest over HistGradientBoosting: RF wins AUC in 7/7 tickers (+0.028 avg). Calibrated probabilities rejected by predefined criterion.
→ Hybrid routing: pool as fallback: NVDA routes to a global model (pool AUC 0.539 vs individual 0.501). Others stay individual — TSLA is too idiosyncratic for pooling.
→ Real sentiment via NewsAPI.ai: 4,303 articles fetched, VADER-scored and aggregated daily. GDELT blocked from this network; free plan archives ~60 days.
→ Leakage tests in CI: tests verify no feature correlates ≥0.95 with the target.

The honest outcome

LightGBM breakthrough After 12 failed improvements, LightGBM + ensemble RF+LGB finally beats RF alone: +0.007 AUC average (6/7 tickers), +0.058 accuracy average. LightGBM wins AUC in 4/7, ensemble wins in 6/7. Different model biases (bagging vs boosting) complement each other.
Model comparison RandomForest wins AUC in 7/7 tickers over HistGradientBoosting (+0.028 avg). Accuracy improved from 54.1% → 57.7% after tuning Optuna with walk-forward as the objective.
The value is the evaluation rigour, not the model performance: knowing when a model does not work is precisely what protects real capital. The single-split evaluation inflated results by +3.6pp — only walk-forward revealed the true picture. After 12 failed attempts, the breakthrough came from combining models with different inductive biases (RF bagging + LGB boosting), not from more features or more complexity. This is the foundation for the portfolio manager system in development.

architecture

Data pipeline & architecture

The codebase is structured into 16 modules under inversion/, each with a single responsibility. Data flows through a deterministic DAG: raw OHLCV → features → sentiment → targets → train → evaluate → serve.
inversion/data
OHLCV fetchers (yfinance, Polygon), cache layer, split strategies (temporal/walk-forward)
inversion/features
Technical indicators (RSI, MACD, BBands, ATR), rolling windows, lagged features, cross-ticker aggregates
inversion/sentiment
VADER scorer, NewsAPI.ai article fetcher, daily aggregation, time-aligned with OHLCV
inversion/models
Per-ticker Random Forests, pooled global model, ONNX export, probability calibration
inversion/tuning
Optuna with walk-forward AUC objective, pruning, Bayesian search, 200 trials/ticker
inversion/backtest
Walk-forward backtest with costs (0.1% commission + 0.05% slippage), Sharpe, max drawdown
inversion/api
FastAPI endpoints, prediction routing, health check, Swagger docs
inversion/monitoring
PSI drift detection, model retrain triggers, prediction logging, alerting hooks

backtest

Out-of-sample backtest with costs

A walk-forward backtest simulates daily trading: enter on BUY signals, exit on SELL, with realistic frictions. This is the closest thing to "how would this actually perform?"
Model strategy return
53.59%
Buy & Hold return
281.70%
Costs applied
0.1% commission + 0.05% slippage per trade
Verdict
Model underperforms buy & hold. Demonstrates rigor, not profitability.
The strategy with model predictions + costs (0.1% commission + 0.05% slippage) yields 53.59% vs 281.70% for simple buy & hold. This confirms the project's core thesis: honest evaluation is the value. A model that underperforms buy & hold is better than a model that overfits and hides behind inflated metrics.
limitations

Limitations & robustness

→ Magnitude of improvement: The model beats persistence on AUC in all 7 tickers, but accuracy gains are inconsistent (positive for 4/7, negative for 3/7). Ranking is better than point prediction — typical for low signal-to-noise domains.
→ Robustness across regimes: The model was trained on 2007–2026 data including the 2008 crisis, 2020 pandemic, and various bull/bear markets. Performance varies by regime — this is expected and honest.
→ Economic utility: Better predictions do not automatically translate to profitable strategies. The backtest with realistic costs confirms this. The project is a technical exercise in rigorous evaluation, not a trading system.
→ Monitoring & drift: PSI (Population Stability Index) monitoring is in place but the system has not been deployed in production for a full market cycle. Retrain triggers are defined but untested at scale.
failed improvements

12 failures → 1 breakthrough

After the baseline was established, 12 systematic improvement attempts were implemented and tested. None surpassed the original Random Forest. This is the honest record — documenting failures is what separates rigorous evaluation from cherry-picked results.
# Improvement Result Δ AUC
1 HGB tuning (Optuna) Worse than RF individual −0.028
2 Ensemble (RF + HGB + RF-sent) Worse than RF alone −0.005
3 Macro features (VIX, sectors, treasury, DXY) Noise overwhelms signal −0.034
4 Advanced features (Hurst, entropy, Roll's spread) No change from baseline ±0.000
5 Stacking meta-learner Meta-learners worse than base −0.012
6 SHAP top-5 feature selection Removing context hurts generalization −0.014
7 ElasticNet (strong regularization) Marginal improvement (only one) +0.009
8 Regime-specific models (bull/bear/neutral) Per-regime models overfit −0.003
9 Continuous target (regression) R² negative (worse than mean) n/a
10 Diverse ensemble (Linear + RF + HGB) Different biases don't complement +0.002
11 Purged CV + imbalance handling Better methodology, same metrics ±0.000
12 Edgebet formulas (Poisson, BTTS, Over/Under) Football formulas don't transfer ±0.000
★ LightGBM + RF ensemble Breakthrough: 6/7 tickers improve +0.007
Why none worked (until #13): financial time series have inherently low signal-to-noise ratios (~1–5% predictable), markets are semi-formally efficient, and increased model complexity amplifies overfitting rather than capturing real structure. The only marginal gain came from ElasticNet's strong regularization (+0.009 AUC), which suggests the problem benefits from simpler models, not more complex ones. The breakthrough (#13) came from combining models with different inductive biases — RF's bagging + LGB's boosting — not from more features. This is a well-known result in quantitative finance — and the project's honest documentation of the 12 failures + 1 success is the actual contribution.
