dskit · scaffold · harness

Production-grade DS scaffold
with the rules in code.

A copier template that starts ML projects organised, reproducible and production-ready — with an AI harness that governs how agents work on the project, a verifiable backlog, and a definition of "done" enforced in code, not asked of the model.

01
problem What it solves
Most ML failures are not model failures — they are reproducibility and consistency failures. Repetitive setup and inconsistent structure are the primary cause of broken projects. dskit eliminates environment drift and enforces a standard project layout from day one.

02
harness The AI harness

An AI model generates code much faster than a human reviews it. The harness puts the reins on: it lives inside the generated repo, travels with the project and is shared by the whole team.

→ AGENTS.md — the entry point. The first thing any agent reads.
→ init.sh — the gate: environment, harness files, backlog and test suite.
→ harness/featureslist.json — a backlog with verifiable acceptance criteria.
→ harness/progress/ — memory outside the context window: current task and history.
The rule No feature is marked done unless ./init.sh passes in green with real command evidence. That is not a prompt instruction — harness finish applies it in Python, so it cannot be talked around.
03
design Why it's built this way
→ uv over pip/conda — faster resolution, reproducible lockfiles, no hidden global state.
→ Convention over configuration — opinionated defaults reduce decision fatigue without blocking customisation.
→ Production layout, not Kaggle layout — raw vs processed data separated structurally, not by honour system.
→ Sphinx by default — documentation is a first-class deliverable, auto-generated from docstrings.
→ Two agent layers — reasoning agents (lider, explorer, implementer, reviewer) and 30 deterministic Python agents.
→ One resource, one owner — contracts in agents/contracts.py declare what each agent may and may not do, validated by tests.
Ecosystem dskit generated the ClimaSafe project and shares its harness philosophy with MeshHarmes.
